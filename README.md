# استشارة — تواصل مع طبيبك

Patient-only consultation site: request a service (general consultation, lab
reading, prescription review, ECG, diet, treatment plan), chat with the doctor,
and track your tickets. Arabic-first (`lang="ar"`, `dir="rtl"`), static, free to
host. **No medical/reference content here** — this site is deliberately separate
from the doctor site (Rochetta).

- Patient flows are guest-first (no sign-up required to request).
- A shared Firebase Firestore (once configured in `src/lib/firebase/config.ts`)
  syncs tickets + chat to the doctor's inbox in real time. Until then the site
  works on localStorage only (demo mode) — see `FIREBASE_SETUP.md`.

## Stack

- **Next.js 16** (App Router) · `output: "export"` — fully static site
- **React 19** + **TypeScript** (strict) + **ESLint** (`eslint-config-next`)
- **Tailwind CSS v4** (`@tailwindcss/postcss`) + design tokens in `src/styles/`
- **lucide-react** icons · **next/font** Google Fonts (Cairo / Tajawal / Inter)
- **firebase** (lazy-loaded ONLY when config is filled in)
- Deploy: GitHub Pages or any static host (custom domain intended)

## Enabling the shared Firebase database

1. Create a Firebase project (Firestore + Anonymous Auth) — free Spark plan.
2. Fill `FIREBASE_CONFIG` in `src/lib/firebase/config.ts`.
3. `firebase deploy --only firestore:rules` (rules are in `firestore.rules`).
4. Rebuild and redeploy both sites. See `FIREBASE_SETUP.md`.

## Safety rules (kept from the original spec)

- **No automatic clinical output to the patient**: any assistive-engine result
  (OCR of a prescription / ECG reading) is stored on the ticket with
  `visible_to_patient: false` and is only ever phrased by the doctor in chat.
- Service forms block submission when an **emergency checklist** item is checked
  and direct the patient to ER instead.

## Notes

- Brand tokens (colors, typography, contact) live in `src/lib/site.ts` +
  `src/styles/tokens.css`; `assets/css/design-tokens.css` is the fixed reference.
- Tickets + chat persist in localStorage per browser (demo), plus real-time
  Firestore sync for the guest flow once enabled. Account (email/phone) sync
  across devices is a later milestone.
- Attachments are deliberately NOT uploaded to Firestore yet (data-URLs):
  transfer to the doctor happens via the WhatsApp/Gmail forward on success.
